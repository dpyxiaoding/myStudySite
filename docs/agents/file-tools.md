# 文件工具的语义

<Badge type="info" text="Evidence · 三家对读" /> <Badge type="info" text="agent-platform · 证据 · 2026-08-26" />

**「把这个文件里的这段改成那样」——这句话展开成代码，有九个地方可以出错，而其中七个不会报错，只会静默改坏**。Claude Code、codex、deepseek-harness 三家的文件工具契约并排读，五处同构、四处分岔。

- **2000** 两家不约而同的默认读取行数
- **3** codex 定位锚点时的降级档数
- **4** 「先读后写」的四种强制方式
- **0** 把 CRLF 当边角料的家数

## 先说清楚，这件事在解决什么

模型不能直接编辑文件。它能做的只有一件事：**描述一次修改**，然后交给一段确定性代码去执行。所有的难点都在这句描述与那段代码之间的缝里。

**第一，模型手上没有文件**。它手上只有几轮之前读到的一份副本。这份副本可能已经过时——用户在编辑器里存了一次盘，另一个工具改了同一个文件，或者模型自己在上一步改过了。它拿着旧副本描述的修改，落在新文件上会是什么，没有人能保证。

**第二，「这段」这个词需要一个坐标系**。行号会漂：改完第一处，第二处的行号就不对了，而模型算不出新行号——它手上仍是旧副本。用文本本身当坐标又要求这段文本在文件里唯一。两条路各有代价，没有第三条。

**第三，文本不只是字符**。它有编码、有换行符风格、有尾随空白。一个在 Windows 上写的文件被读成字符串、改一个词、写回去，如果中间少了一步，整个文件的每一行都会被标记成改动过——**而 diff 会告诉你它变了，测试不会。**

**第四，写文件是不可逆的**。与读不同，一次错误的写没有撤销键。所以这一组工具是整个 agent 里最需要「宁可拒绝也不要猜」的地方。

九个维度：① 编辑原语 → ② 先读后写怎么强制 → ③ 锚点不唯一与找不到 → ④ 换行符与编码 → ⑤ 读的形状 → ⑥ 路径与符号链接 → ⑦ 改动怎么交出去 → ⑧ 写之外的操作 → ⑨ 审批粒度

## ① 编辑的原语是什么

给模型一把什么形状的凿子：整份重写、替换一段文字，还是一份补丁？

::: info Claude Code / dsh — 字符串替换 — 档 A · 两家几乎一字不差
- 入参四个：路径、`old_string`、`new_string`、`replace_all`
- 默认 `replace_all: false`，此时 `old_string` 必须**恰好出现一次**
- dsh 的文档还补了一句：`new_string` 传空串就是删除这一段
- 另有一把整份覆盖的 `write`，与 `edit` 分开

来源：`工具描述原文` · `dsh docs/tool-catalog.md`
:::

::: codex 一份补丁，多文件多操作 | 全量源码
- 原语是 `Hunk` 三种：`AddFile` / `DeleteFile` / `UpdateFile`，后者还带一个可选的 `move_path`
- **一次调用可以同时增、删、改、移多个文件**
- 一个文件内多个 chunk 必须**有序**：后一个 chunk 的上下文要出现在前一个之后
- 它还能作为独立可执行文件被自调用，有一个专门的 argv 标志走这条路

来源：`apply-patch/src/parser.rs` · `lib.rs`
:::

::: info dsh 的第二把 — 一个带命令的编辑器 — 全量源码 + 工具目录
- `str_replace_editor`：一把工具四个命令——`view` / `create` / `str_replace` / `insert`
- `insert` 按行号插入，**是这一整份对读里唯一按行号定位的写操作**
- 与 `edit` 并存，也就是 dsh 同时提供两套编辑契约

来源：`docs/tool-catalog.md` · `fs/tool-str-replace-editor`
:::

::: warning 分岔
本仓与 Claude Code / dsh 同形：`write` 整份覆盖、`edit` 改一段，分成两把而不是给 `write` 加参数。理由写在头注释里，而且是这一维里最好的一句论证：**它们的失败模式完全不同——覆盖只会因边界或版本失败，而局部修改还会「锚点找不到」「锚点命中多处」，那两种要给模型的话完全不一样。**

codex 那条路的代价与收益都很清楚：一份补丁能表达跨文件的一次原子改动，代价是模型要生成一种带格式的文本，而格式错了整份都用不了——所以它需要一个真正的解析器加一个流式解析器。
:::

## ② 「先读后写」怎么强制

模型没读过就写，是最常见的一种数据丢失。四家给了四种不同层次的答案。

::: claude 契约声明 + 会话状态 | 档 A（契约原文）
- Edit 的第一条：**「你必须在本对话里 Read 过这个文件，否则调用会失败」**
- Write 的对应条：「覆盖一个你没读过的已存在文件会失败」——注意条件是**已存在**，新建不受限
- Read 那边还有一条反向约束：**不要为了确认而重读刚编辑过的文件**，理由写明是「改失败的话 Edit/Write 早就报错了，而且 harness 跟踪着文件状态」

来源：`Read / Edit / Write 工具描述`
:::

::: dsh 一个可插拔的观察策略 | 全量源码
- 一个**只有事件、不注册服务**的插件，用一个弱引用表记下每次权威的「存在 / 不存在」观察
- 写意图从观察状态**推导**：没见过或确认不存在 ⇒ `createIfAbsent`；确认存在 ⇒ `replaceIfVersion` 带上观察到的版本
- 三个错误码分得很干净：`FS_NOT_OBSERVED`（没读过）/ `FS_NOT_FOUND`（读过，确认不存在）/ `FS_STALE_VERSION`（读过，但版本对不上了）
- 关键的一句在头注释里：**不装这个插件，工具就退回裸接口的无条件修改行为**。防护是加上去的，不是内建的

来源：`fs/fs-observation-policy/src/index.ts`
:::

::: ours 做成必填入参 | 本仓源码 · ADR-0051 / ADR-0080
- `read` 的回执带一个全文 `contentHash`；两把写工具的 `expectedContentHash` **必填**
- 于是「没读过的文件改不了」**在类型上就成立**，不需要任何运行时状态跟踪
- 头注释写明它挡的是哪条路径：模型读了、想了两轮、期间用户在编辑器里存了一次盘，模型把记忆里那一版改完写回去——**用户那次改动无声消失**

来源：`packs-coding/src/expected-version.ts`
:::

::: info codex 这一格是隐式的。
`apply_patch` 的每个 chunk 都带上下文行，而上下文行必须能在文件里找到——所以「不知道文件长什么样就改不了」是补丁格式的副产品，不需要另一道闸。代价是这道闸**只挡住了「完全没看过」，挡不住「看的是旧版本」**：上下文行还在、但文件其他地方被人改过，补丁照样应用成功。
:::

::: tip 同构，但强度差三档
四家都认为「先读后写」是必须的，分岔在把它放在哪一层：**契约里说（Claude Code）、可插拔的策略层（dsh）、必填入参（本仓）、格式的副产品（codex**）。强度从弱到强正好是这个顺序——本仓那一档最硬，因为它是编译期的。

dsh 那一格最值得记的是它的形态：**它把「先读后写」实现成了文件版本上的乐观并发控制**——读一次拿到版本，写的时候带着版本比对，不一致就拒。这与本仓的 `contentHash` 是同一个东西的两种写法，而 dsh 把它做成了可拆卸的，本仓做成了不可拆卸的。
:::

## ③ 锚点找不到，或者命中多处

这是字符串定位那条路唯一的软肋，也是三家差别最大的一格。

<figure class="diagram">
<!--@include: ./figures/file-tools-1.svg-->
<figcaption>同一个「找到要改的那一段」的问题，两种解法。左边把不确定性直接退回给模型，让它自己解决；右边在代码里吸收一部分不确定性，代价是有可能匹配到一个模型没打算改的位置。</figcaption>
</figure>

::: codex 三档降级，且特例带日期 | 全量源码
- 匹配按**递减严格度**尝试：精确 → 忽略行尾空白 → 忽略首尾空白
- 带文件结尾标记的块**先从末尾开始试**，让意在匹配文件结尾的模式落在结尾，失败再回到起点搜
- 两条防御性特例写在注释里：空模式返回无操作命中；模式比文件长直接返回未命中——后者注明是「**避免 2025-04-12 之前出现过的越界 panic**」

来源：`apply-patch/src/seek_sequence.rs`
:::

::: dsh 两个错误码 | 全量源码
- 搜索文本为空或找不到 ⇒ `FS_EDIT_NOT_FOUND`
- 命中多处且没传 `replaceAll` ⇒ `FS_AMBIGUOUS_EDIT`
- 没有任何降级：**字面替换就是字面替换**

来源：`fs/fs-local/src/fsio.ts`
:::

::: info Claude Code / 本仓 — 不降级，本仓留了一处 — 档 A / 本仓源码
- Claude Code 的契约：必须精确匹配**包括缩进**，且必须唯一，否则编辑失败
- 还有一条很实在的坑：**比对前要先剥掉 Read 输出的行号前缀**——读出来带行号，改的时候不能带
- 本仓把这一格写成了拆两把工具的理由本身：「锚点找不到」与「锚点命中多处」是 `edit` 独有的两种失败
- 但它有**恰好一处**放松：先精确比，比不上再按目标文件的换行符换算一次锚点。换算锚点而不是把文件折平了再找，理由是**折平之后命中位置要映射回原文偏移，而换算锚点则唯一性检查一行都不用改**

来源：`Edit 工具描述` · `packs-coding/src/edit-file-tool-provider.ts`
:::

::: warning 分岔 · 真正的问题不是降不降级，是判据
**codex 在代码里吸收模糊性，另外三家把模糊性退回给模型**。两边各有失效方式：降级匹配可能匹配到一个模型没打算改的位置——忽略首尾空白之后，缩进不同的两段代码看起来是同一段；不降级则会在「模型多抄了一个尾随空格」这种小事上失败一次，多花一轮。

本仓表面上站在不降级那边，但实际有**恰好一处**放松：锚点先精确比，比不上再按目标文件的换行符换算一次。而它给这一处例外写了一条判据，是这一整份对读里最好的一句：**换行符这一条有资格特殊，是因为它不是内容的一部分而是文件的存储形态，且归一化发生在模型那一侧、不是用户写错了**。空白、缩进、引号一律照旧逐字符比。

这条判据把「降不降级」这道题换了个问法：不是宽容多少，而是**这个差异到底是谁造成的**。模型在复述时被迫丢掉的东西可以补回来，模型自己抄错的东西不能。codex 的三档降级里，「忽略行尾空白」大致落在前者，「忽略首尾空白」落在后者——两档挤在同一个阶梯上。
:::

## ④ 换行符与编码

这一维没有一家把它当边角料，而且三家的答案精细度差了整整一个量级。

::: codex 逐行记住自己的结尾 | 全量源码 · 最细的一档
- 换行符是**三值**：`Lf` / `CrLf` / `Cr`（老 Mac 那一种也在）
- 文件被切成行，**每一行各自记住自己的结尾**——不是整个文件一个风格
- 「第一个出现的结尾」成为插入新行时的风格；完全没有结尾的文件默认 LF
- 另有一个显式的两档模式：`NormalizeToLf`（默认，注释写明是「保留历史行为」）与 `PreserveLineEndings`，通过一个环境变量传给独立可执行文件那条路

来源：`apply-patch/src/text_file.rs` · `lib.rs`
:::

::: dsh 检测多数派，写回时还原 | 全量源码
- 读的时候取**前 4096 个字符**做样本，数 CRLF 与 LF 哪个多，多的那个是这个文件的风格
- 内存里一律规范成 LF，注释说明这是「每一个编辑与 diff 基准使用的规范形式」；**落单的 `\r`（后面没跟 `\n` 的）原样不动**
- 写回时还原成检测到的风格，而 CRLF 那一支**先规范化再转换**——注释写明理由是「让一个已经是 CRLF 的序列永远不会被翻倍成 `\r\r\n`」

来源：`fs/fs-local/src/fsio.ts`
:::

::: ours 同一条路，起点是一次真机故障 | 本仓源码 · issue #83
- 判据是「**CRLF 占了一半以上的换行」而不是「出现过 CRLF**」，理由写明：混排文件里少数几个 CRLF 不应该让整份被改写成 CRLF
- 还原函数**先折平再展开，所以对已经是目标形态的文本是恒等的**——与 dsh 那句「永远不会翻倍成 `\r\r\n`」是独立撞出的同一条
- 写回时按**目标文件**的换行符，不按模型给的那份：模型复述文本时会把 CRLF 归一成 LF，照它写回等于顺手改掉这几行的换行符——而它既没打算改，也没有别的办法表达
- 整份覆盖时同理，且注释记下了这两件事叠加的后果：**一次「改三行」会把整份 CRLF 文件换成 LF，在 git 里全红**，真机上已经发生过一次

来源：`shared/src/line-endings.ts` · `packs-coding/src/{edit,write}-file-tool-provider.ts`
:::

::: info Claude Code 这一格是空的，但空的原因是不可读，不是没做。
工具描述里没提换行符也没提编码。唯一沾边的是 Read 的输出格式（`cat -n`），而那意味着模型看到的换行已经被渲染过一道。
:::

::: tip 同构 · 三家独立撞出同一套三步
读时检测、内存里规范成 LF、写回时还原——codex、dsh、本仓三家都是这三步，而且都在注释里留下了具体踩过的坑（翻倍成 `\r\r\n`、落单的 `\r`、老 Mac 的单 `\r`、整份文件在 git 里全红）。**没有一家把 CRLF 当边角料，也没有一家是先设计后遇到的——三处注释里都能读出这是踩出来的。**

「还原必须幂等」这一条尤其值得记：dsh 与本仓各自写了一句几乎一样的注释，而它们不可能互相抄。这种独立重合是最强的一类证据——**说明这不是风格选择，是这条路上必然会撞到的那块石头。**

剩下的差别是精细度：codex 逐行记住各自的结尾、换行符是三值（含老 Mac 的单 `\r`）、新行用文件里第一个出现的风格；dsh 与本仓都是整份取多数派，dsh 取前 4096 字符做样本、本仓统计全文。**逐行保真那一档，另外两家都没有。**
:::

## ⑤ 读的形状：多少、什么格式、怎么标截断

读是写的前提，而读回来的形状直接决定模型能不能写对。

::: info 两家不约而同的 2000 — 档 A · 契约层
- Claude Code 的 Read：默认最多 2000 行，结果用 `cat -n` 格式、行号从 1 起
- dsh 的 `read`：`offset` 从 1 起、`limit` **默认 2000**，返回带行号的内容
- 两边的入参形状与默认值几乎一字不差
- Claude Code 另有一条：读目录、读不存在的文件、读空文件**返回错误或提示，而不是内容**——空字符串会被模型读成「这个文件是空的」，那是错的

来源：`Read 工具描述` · `dsh docs/tool-catalog.md`
:::

::: info 非文本各有各的路 — 档 A / 全量源码
- Claude Code 的 Read 一把工具吃三类：文本、图片、PDF（按页读，单次最多 20 页，超过 10 页的必须指定页范围）、Jupyter（按 cell 带输出）
- dsh 拆成两把：`read` 只吃 UTF-8 文本，图片走 `read_image`，而且工具描述里明写「**harness 会在下一次请求前校验并缩小大图，所以直接用这把工具，不要为了看一眼图去装图像库或做缩略图**」

来源：`Read 工具描述` · `dsh docs/tool-catalog.md`
:::

::: ours 按字符截断，给人另发一份 | 本仓源码
- 截断按**字符数**而不是行数，截断了在正文末尾缀一行「内容超过 N 字符，已截断」
- 理由写得很具体：**屏幕上内容突然断掉时，用户分不清「文件就这么长」与「我们截了」**，而后者要他换个区间再读一次
- 行号那一份还有一条细节：**末尾的空行照编号、不吞掉**——吞掉会让屏幕行数比回执里那句「读取 N 行」少一行，两处对不上比多一个空行更难解释

来源：`packs-coding/src/tool-body.ts`
:::

::: tip 同构
三家都给读加了行号，而且都把「截断了」做成一个**显式的事实**而不是静默省略。dsh 的 `str_replace_editor` 甚至有一个专门的标记文本 `<response clipped>`。

Claude Code 那条「读目录、读空文件返回错误而不是内容」值得单独记：**空内容与空文件在字符串层面无法区分，而对模型来说这是两个完全不同的事实**。本仓的 `read` 在这一格没有对应的显式处理。
:::

## ⑥ 路径与符号链接

路径校验通过之后到真正写下去之间，文件可以被换掉。这个窗口怎么处理？

::: ours 三段式，第三段不许重新解析 | 本仓源码 · ADR-0035 / ADR-0036
- 写法是三段：解析 → 在风险评估里声明资源占用 → 在执行里**消费已校验的那一份**
- 第三段**不许从原始入参重新解析路径**，理由写明：同一份入参在校验时与执行时可以指向两个不同的文件（换一个符号链接就行），而入参哈希全程不变——**重新解析等于把前两段建立的保证在最后一步扔掉**
- 版本检查特意放在紧贴写入调用的位置，理由是**这个窗口只能收窄不能关闭，那就该往小里收**

来源：`packs-coding/src/read-file-tool-provider.ts` · `expected-version.ts`
:::

::: codex 跟不跟符号链接是一个显式开关 | 全量源码
- `ApplyPatchOptions` 上有一个 `follow_symlinks`，注释说明「**独立调用方默认跟随**」
- 测试里有一个专门的 `no_follow` 场景文件
- 文件操作走的是执行器的文件系统接口，带沙箱上下文，不是直接的系统调用

来源：`apply-patch/src/lib.rs` · `tests/suite/no_follow.rs`
:::

::: dsh 沙箱是单独一个包 | 全量源码
- `fs-sandbox` 与 `tool-fs/src/sandbox.ts` 各一层
- 路径解析的责任明确归给后端：每把工具的 schema 里都写着「**由文件系统后端解析**」
- 会话工作目录也是单独一个模块

来源：`fs/fs-sandbox` · `fs/tool-fs/src/{sandbox,session-cwd}.ts`
:::

::: tip 同构
三家都把「路径怎么解析」从工具实现里拿出去，交给一个统一的层——codex 交给执行器的文件系统接口，dsh 交给文件系统后端，本仓交给风险评估那一段并要求执行段不得重解析。共同的判据是一句：**校验和执行必须看到同一个文件。**

codex 那个 `follow_symlinks` 默认跟随、且有专门的测试场景，说明这是踩出来的一格。本仓的对应处置更严：不是开关，是结构上不给重新解析的机会。
:::

## ⑦ 改动怎么交出去

改完了。要给模型看什么、给人看什么，这两份是不是同一份？

::: dsh 回执带「改之前」的原文 | 全量源码
- 写的结果里带三样：这次是**创建还是更新**、新版本号、以及**写之前的内容**
- 那份旧内容的说明很讲究：它是 **LF 规范化的存储文本（diff 的基准），永远不是一份 diff**——怎么呈现由消费者决定
- 文件是二进制或非 UTF-8、或者两侧任一超过限额时，这一项给空，而不是给一份残缺的基准

来源：`fs/fs/src/types.ts` · `FsWriteOutcome`
:::

::: codex 补丁本身就能渲染成 diff | 全量源码
- crate 直接导出把 chunk 转成 unified diff 的函数，还有一个带上下文行数参数的版本
- 回合级另有一个改动聚合器，协议里 `turn/diff/updated` 推的就是聚合后的 unified diff
- 也就是「**给人看的 diff」在它那里是一等公民**，不是事后拼的

来源：`apply-patch/src/file_update.rs`
:::

::: ours 两份，且明确说明为什么是两份 | 本仓源码
- 结构化回执给模型，另发一份纯文本正文给人，**回执一个字节不改**
- 起因很具体：回执被压成一行 JSON 之后，文件正文里的换行变成两个字面字符，**屏幕上铺出一堵单行 JSON，行数闸门完全失效**——它数的是真换行，而真换行只剩 0 个
- 修法不是让渲染层去拆 JSON：**渲染层不许认字段名、更不许认工具名**（两条产品线两套工具集，企业侧入参带 PII），所以「谁最清楚哪一段该给人看，就由谁给」

来源：`packs-coding/src/tool-body.ts`
:::

::: warning 分岔
三家都区分了「给模型的」与「给人的」，但拆的位置不同：dsh 在**数据层**拆（回执带原文，怎么画由上层定），codex 在**协议层**拆（diff 是一等的推送类型），本仓在**工具层**拆（工具自己发两份，走不同的敏感度）。

本仓那条「渲染层不许认字段名」是三家里唯一被写成硬约束的，而理由是本仓独有的：两条产品线共用一个渲染层，企业侧的工具入参里会有 PII。另外两家都只有一条产品线。
:::

## ⑧ 写之外：创建、删除、移动

「改文件」只是一半。新建、删掉、改名这三件事归谁管？

| 操作 | Claude Code | codex | deepseek-harness | 本仓 |
| --- | --- | --- | --- | --- |
| 新建文件 | Write（不要求先读） | `AddFile` hunk | `write` / `str_replace_editor` 的 `create` | `write`，用「文件不存在」哨兵 |
| 删除文件 | 无专门工具，走 Bash | **`DeleteFile` hunk** | 无专门工具 | 无专门工具 |
| 移动 / 改名 | 无专门工具，走 Bash | **`UpdateFile` 的 `move_path`** | 无专门工具 | 无专门工具 |
| 删除一段文本 | Edit，`new_string` 传空 | 补丁里的减号行 | 同 Claude Code，文档明写 | `edit`，同形 |

::: warning 分岔 · 且这一格有安全含义
只有 codex 把删除与移动做成了**结构化工具的一部分**；另外三家（含本仓）都要走 shell。这个差别不只是方便与否——**走 shell 意味着这两个动作的风险判定落在命令解析器上，而不是落在一个有明确入参的工具上。**

本仓 `command-risk.ts` 已经出过一次漏判形状（#172），而「删文件」正是那类判定器最难判准的东西之一（通配符、变量展开、\`find -delete\`）。把删除做成结构化工具，等于把这一类判断从字符串解析挪回参数校验——这是本仓可以考虑的一条。
:::

## ⑨ 审批粒度：为什么这一组可以按组免检

「让它改文件，别再问我」——这句话该覆盖多大范围？

《沙箱与权限的三种解法》那一份从 shell 一侧讲过审批。文件工具这一侧有一个结构性差异，本仓把它写成了一段完整论证，而且它同时回答了「为什么同一句论据不能套过去」：

> ADR-0076 否决过 (工具名 + 风险档) 这个粒度，理由是批准 pnpm test 之后 echo x > src/main.ts 会被同一条记忆放行。那条理由是针对 bash 的：bash 无界，批一次等于批准执行任意代码。这两把工具结构上不是一回事——只能写不能执行；被工作区边界与敏感文件基线钉住，而那两道都不经过审批；expectedContentHash 必填，没读过的文件改不了；每一次都进 ChangeSet，逐文件复核得到。
>
> —— `packs-coding/src/file-edit-exemption.ts`

四条理由里有三条是这一整份对读讨论过的东西：**边界（⑥）、先读后写（②）、改动可复核（⑦**）。也就是说前面八维的设计共同支撑了第九维的一个结论——文件工具可以按组免检，而 shell 不行。

另外两家的对应处置：Claude Code 有一个 `acceptEdits` 权限档，**整档放行文件类工具**，与本仓的按组免检是同一个形状；codex 的审批策略是 per-step 的，且文件写入走执行器的沙箱上下文。

::: tip 同构
两家独立撞出「文件编辑可以作为一组一次批准」这个粒度，而两家都没有对 shell 这么做。这不是巧合——**可以按组批的前提是这一组的能力上界是封闭的，而 shell 的上界是开放的。**
:::

## 对本仓意味着什么

### 同构 —— 三家都这么做，可以当定论

- **先读后写不可省**。四家全有，只是强度不同，本仓那一档最硬。
- **整份写与局部改分成两把工具**。三家同形，而本仓写下的理由（失败模式不同）是其中最完整的一句。
- **读要带行号、截断要显式**。三家一致。
- **路径解析与执行必须看到同一个文件**。三家各有各的做法，判据同一条。
- **文件编辑可以按组一次批准，shell 不行**。两家独立撞出同一个粒度。
- **换行符要读时检测、内存规范、写回还原，而且还原必须幂等**。三家（含本仓）独立走到同一套三步，dsh 与本仓甚至写了几乎一样的幂等注释。本仓这一格已经做完，不必补。

### 本仓没有 —— 补不补是决策，本文不作

- **逐行的换行符保真**。本仓与 dsh 都是整份取多数派，而 codex 让每一行记住自己的结尾、并把老 Mac 的单 `\r` 也算一档。多数派做法在混排文件上会把少数派那几行一起改掉——本仓的注释已经知道这一点（判据特意写成「占一半以上」而不是「出现过」），但知道不等于处理了。
- **空文件与不存在的区分**。Claude Code 的 Read 对读目录、读空文件返回错误而不是空内容。空字符串会被模型读成「这个文件是空的」，而它可能是「这个路径根本不是文件」。
- **结构化的删除与移动**。只有 codex 做了。收益不在方便，在于把这两类动作的风险判定从命令字符串解析挪回参数校验——而 `command-risk.ts` 已经在这类形状上漏判过一次。
- **写回执带「改之前的内容**」。dsh 把它做成数据层的一等字段，并明确它是 diff 的基准而不是 diff。本仓的 ChangeSet 走的是另一条路，两者可以对照一次。

### 三家分歧 —— 要自己判，没有现成答案

- **锚点失配要不要降级，以及凭什么降**。codex 在代码里吸收模糊性，另外三家退回给模型。本仓的位置最特别：只放松换行符一处，判据是「这不是内容，是存储形态，且归一化发生在模型那一侧」。这条判据可以直接拿去检验 codex 那三档——它的「忽略行尾空白」大致站得住，「忽略首尾空白」站不住。要不要再放松一格，得先问这个差异是谁造成的。
- **编辑原语是不是补丁**。补丁能表达跨文件的一次原子改动，代价是需要一个真正的解析器，且格式错了整份作废。
- **「给人看的那一份」在哪一层拆**。数据层、协议层、工具层各一家。本仓选工具层的理由是独有的（两条产品线共用渲染层、企业侧入参带 PII），所以这一格不必跟。

## 证据档次与没核到的部分

这一份的证据结构与前几份不同：**Claude Code 这一列反而最实**，因为文件工具的契约就是工具描述本身，可以逐字读到，而契约在这一维里就是行为的一半。codex 与 deepseek-harness 仍是全量源码。凡是写「未核到」的格子都是真的没读到。

### 明确没核到的

- Claude Code 的换行符与编码处理、路径与符号链接策略、改动怎么呈现——契约层不提，实现层不可读
- Claude Code 的 Edit 判唯一性的具体实现与失败时回给模型的原话
- dsh 的审批粒度（`interaction` 包组这一轮没读）
- codex 有没有与 `expectedContentHash` 等价的版本冲突保护——它的上下文行只挡「完全没看过」，挡不住「看的是旧版本」，**是否另有一道闸，我没核到**
- 三家都没有跑起来做行为实测；本仓那条 CRLF 教训是本仓自己的真机记录
