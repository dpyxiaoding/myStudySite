# 回合循环与中断：三家差异

本篇把 Claude Code、codex、deepseek-harness（下文简称 dsh）的回合循环放在一起比较。小节和三家各自的页面一一对应，每节先列对照表，再说哪里一样、哪里不一样。各家的细节和出处在各自的页面里，每节末尾有链接。

三家的官方术语表对 turn 的定义说的是同一件事：从一条消息进来，到智能体答完、把控制权交还给你。本篇的「一轮」就是这个意思。一轮里模型会被请求好几次，dsh 把每次请求加上随后的工具执行叫作「步骤」，另外两家没有给这一层单独起名，本篇就直接说「每次请求模型」。

::: info 依据
- 和三家页面用的是同一批资料：Claude Code 2.1.296，codex rust-v0.162.1（源码提交 `092d3ac`），dsh 0.2.1-alpha.2（源码提交 `d743267`），2026-10-12 核对。
- 证据的分量不一样：codex 和 dsh 读的是源码，Claude Code 引擎不公开，依据是官方文档。表里 Claude Code 写「文档没写」的格子，不代表它没有这个机制。
:::

## 一句话

三家的循环骨架相同：请求模型，回复里有工具调用就执行，把结果交回去再请求，直到模型不再要求调用工具。差别都在循环的边上：

| | 工具什么时候开始跑 | 回复写到一半出错 | 干活时插话 | 中断后给模型的说明 |
| --- | --- | --- | --- | --- |
| Claude Code | 文档没写 | 已有完整内容就不重发，接着跑 | 这批工具跑完后交给模型 | 文档没给原文，记录里有一段以 `[Request interrupted by user` 开头的标记 |
| codex | 回复里的工具调用一完整就开跑 | 保留完成的部分，等工具跑完，用新历史重试 | 模型正在输出就截断，带着插话重新请求 | 加一段 `<turn_aborted>`：用户是故意打断的，命令可能执行了一半 |
| dsh | 整条回复成功才开跑 | 整条作废，这一步原样重发 | 在下一步开头领取 | 不另加说明，半截回复和工具的错误结果留在历史里 |

### 三家一样的地方

- **插话不改已经发出去的请求。** 插话要么在两次请求之间交给模型，要么像 codex 那样先截断这次输出、再带着插话重新请求。没有一家往一个已经发出去的请求里塞内容。
- **每个工具调用都要配一个结果。** 中断、出错、进程崩溃之后，三家都给没有结果的调用补上结果，因为模型接口不接受「有调用、没结果」的历史。
- **重试不能让工具执行两遍。** 三家的做法不同，目标一样，见[出错了怎么办](#出错了怎么办)。
- **工具出错不算这一轮出错。** 失败、被拒绝、超时，都作为这个调用的结果交给模型，由模型决定接下来怎么做。
- **结束原因是一组固定的取值。** 「用户中断」「出错」「正常答完」在记录里是不同的值，不会都算成「失败」。
- **答完之后还能让它接着干。** Claude Code 和 codex 有 Stop 钩子，dsh 有插件检查点 `agent/turn-stopping`。三家也都有 `/goal`，没完成就自动续跑。

### 三家不一样的地方

- **工具和回复的先后**：codex 边收回复边开跑工具，dsh 等整条回复成功才跑，Claude Code 文档没写。这直接决定了出错时怎么重来，见[出错了怎么办](#出错了怎么办)。
- **哪些工具能并发**：codex 里几条 shell 命令可以同时跑，Claude Code 和 dsh 都不行。见[几个工具一起调](#几个工具一起调)。
- **插话截不截断模型的输出**：只有 codex 截断。见[跑动中插话](#跑动中插话)。
- **中断后排队的消息去哪**：Claude Code 立刻发出去，codex 放回输入框，dsh 留在队列里等你下次发消息。见[按下中断之后](#按下中断之后)。
- **有没有上限、有没有防打转**：只有 Claude Code 在非交互模式下能设步数和花费上限；只有 dsh 默认提醒重复调用。见[什么时候停](#什么时候停)。

## 你能看到和操作的

| | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 干活时发消息 | 回车，这批工具跑完后在同一轮里交给模型；`Ctrl+Enter` 立刻发 | 回车插进这一轮；`Tab` 排到下一轮 | 回车默认排到下一轮，`Ctrl+Enter` 插进这一轮，设置里可以对调 |
| 中断 | `Esc`，或有任务时按 `Ctrl+C` | `Esc`，或有任务时按 `Ctrl+C` | 0.5 秒内连按两次 `Esc`，或点停止按钮 |
| 步数上限 | `--max-turns`，只在 `-p` 模式下有效 | 没有 | 没有 |
| 花费上限 | `--max-budget-usd`，只在 `-p` 模式下有效 | 没有；目标可以设 token 预算 | 没有；目标有轮数上限 |
| 重试次数 | `CLAUDE_CODE_MAX_RETRIES`，默认 10 | 输出流中断 5 次、发请求失败 4 次，按模型提供方配置 | 模型提供方的 `retryPolicy`，默认 5 次 |
| 答完时的钩子 | Stop，可以让它接着干 | Stop，可以让它接着干 | 没有配置文件式钩子，插件监听 `agent/turn-stopping` |
| 中断时的钩子 | 没有；Stop 不运行 | Interrupt，只能记录和清理 | 没有专门的钩子 |
| 程序里插话 | SDK 发消息时带 `priority` | app-server 的 `turn/steer` | Agent 的 `steer()` |

**插话和排队的默认键，三家各不相同。** Claude Code 里干活时打字回车，消息在这一轮里交给模型，没有「排到下一轮」的按键（斜杠命令和 `!` 命令会等这一轮结束）。codex 用回车插话、`Tab` 排队。dsh 反过来，回车默认排队，因为它的默认设置是「忙时 Enter 排队」，想改成插话可以在设置里对调。

**只有 Claude Code 能在命令行里设上限。** 而且只在非交互的 `-p` 模式下有效，交互界面三家都靠人看着。

## 一轮是怎么跑的

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 定义出处 | 术语表 Turn | 术语表 Turn；一轮由条目（item）组成 | 术语表「轮次」 |
| 一轮里面那一层 | 术语表没有命名；`--max-turns` 数的是其中带工具调用的回复次数 | 源码里叫一次采样请求 | 术语表「步骤」 |
| 要不要再请求一次 | 回复里有工具调用 | 回复里有工具调用，或者又来了插话，或者服务端标了 `end_turn: false` | 回复里有工具调用；没有的话，收尾检查后又来了插话 |
| 除了你的消息，还有谁会开启一轮 | 后台任务完成、定时任务、别的会话发来的消息、`/goal`、用量额度恢复、进程重启后续跑 | `Tab` 排队的消息、子代理来信、目标续跑、客户端自己跑的工具结果 | 定时任务、后台任务完成、子代理来信、目标续跑 |

**一样：一轮不只由你开启。** 后台任务完成、定时任务到点、子代理发来消息，三家都会自动开启新的一轮。所以「一轮」对应的不总是你敲的一次回车。

**不一样：模型答完时刚好来了插话。** codex 和 dsh 在同一轮里再请求一次模型，把插话交给它。Claude Code 让这一轮正常结束，插话作为下一轮的第一条消息发出去。

**不一样：dsh 的一步是一个整体。** dsh 要等整条回复成功收到，才开始执行里面的工具；codex 是工具调用一完整就开跑，不等回复结束。Claude Code 的钩子文档提到工具调用可能在模型还在输出时就执行完了，但没有说从哪一刻开始。

**只有 dsh 写明了撞上输出上限怎么办。** 回复里的工具调用全部丢掉不执行，这一轮以 `max-tokens` 结束。另外两家的资料里没有说明。

细节：[Claude Code](/agents/claude-code/turn-loop#一轮是怎么跑的) · [codex](/agents/codex/turn-loop#一轮是怎么跑的) · [dsh](/agents/deepseek-harness/turn-loop#一轮是怎么跑的)

## 几个工具一起调

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 怎么判断能不能并发 | 看工具是否只读 | 工具自己声明，拿读锁的可以同时跑，拿写锁的独占 | 每次调用按参数判断（`isConcurrencySafe`） |
| 默认能并发的 | Read、Glob、Grep，标了只读的 MCP 工具 | 跑命令的 `exec_command`、`write_stdin`，`view_image`、`tool_search`，标了只读或服务器配了并发的 MCP 工具 | `read`、`read_image`、`web_fetch`、`web_search`、`subagent`、`subagent_fork` |
| 独占的 | Edit、Write、Bash | 改文件的 `apply_patch` 等没声明的 | `bash`、改文件、`grep`、`glob`、MCP 工具 |
| 同时最多 | 10 个（只读工具和子代理合计） | 源码里没有数量上限 | 10 个 |
| 结果的顺序 | 文档没写 | 按模型给出调用的顺序 | 按模型给出调用的顺序 |

**一样：没声明就不并发。** Claude Code 的自定义工具要标 `readOnlyHint` 才能并发；codex 工具的默认值是不支持并发；dsh 没有判断函数、函数报错、返回值不是 `true`，一律按独占处理。

**不一样：shell 命令。** codex 让 `exec_command` 并发，几条命令可以同时跑，改文件则一次只改一处。Claude Code 和 dsh 都把 shell 命令当成独占的。dsh 连 `grep`、`glob` 也是独占的，Claude Code 的 Glob、Grep 可以并发。

**不一样：判断的粒度。** Claude Code 和 codex 按工具判断，同一个工具要么都能并发、要么都不能。dsh 的判断函数能看到这次调用的参数，同一个工具的不同调用可以分开对待；而且每个调用开始前都重新判断一次。

细节：[Claude Code](/agents/claude-code/turn-loop#几个工具一起调) · [codex](/agents/codex/turn-loop#几个工具一起调) · [dsh](/agents/deepseek-harness/turn-loop#几个工具一起调)

## 跑动中插话

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 什么时候交给模型 | 这批工具跑完、下一次请求之前 | 下一次请求之前 | 下一步开头 |
| 正在输出的回复 | 不打断 | 立刻截断，带着插话重新请求 | 不打断 |
| 正在跑的工具 | 不打断；`Ctrl+Enter` 会把能挪的挪到后台，挪不了的就中断这一轮 | 不打断，等它们跑完 | 不打断 |
| 模型答完时刚好来了插话 | 这一轮结束，插话开启下一轮 | 同一轮里再请求一次 | 同一轮里再走一步 |

**一样：插话交给模型的位置。** 三家都在「一批工具跑完、下一次请求之前」把插话交给模型，正在跑的工具都不会被插话打断。

**不一样：codex 会截断模型的输出。** 模型正在写回复时你插了话，codex 立刻停止接收这次输出，已经完整的条目保留，没写完的丢掉，然后带着插话重新请求。这个行为由 `instant_interrupt` 控制，标为开发中，但默认打开。好处是模型不用把一段可能已经过时的回复写完；代价是这段回复白写了。Claude Code 和 dsh 都让模型把这次回复写完。

**不一样：Claude Code 的「立刻发」是另一种思路。** 按 `Ctrl+Enter` 时，Claude Code 不截断模型，而是把在跑的 shell 命令、子代理这类活挪到后台继续跑，模型在同一轮里读到你的话；只有模型正在写回复、或者手上的活挪不到后台时，才中断这一轮。

细节：[Claude Code](/agents/claude-code/turn-loop#跑动中插话) · [codex](/agents/codex/turn-loop#跑动中插话) · [dsh](/agents/deepseek-harness/turn-loop#跑动中插话)

## 按下中断之后

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 半截的回复 | 截断；是否留在历史里文档没写 | 没写完的条目丢掉 | 已经显示的部分留在历史里，标 `interrupted: true` |
| 在跑的工具 | 取消，结果写明被中断 | 最多等 100 毫秒，然后终止，结果写成 `aborted by user after 2.3s` | 收到取消信号，交出自己的结果 |
| 没开始的工具 | 文档没写 | 不存在，工具调用一完整就已开跑 | 补一条 `Error: tool call aborted before dispatch` |
| 给模型的说明 | 文档没给原文，记录里有以 `[Request interrupted by user` 开头的标记 | `<turn_aborted>` 一段说明 | 不另加说明 |
| 排队的消息 | 马上发出去 | `Tab` 排队的放回输入框；还没送达的插话立刻作为新一轮发出 | 留在队列，不自动开始下一轮 |
| 结束记成 | `aborted_streaming`（断在输出时）或 `aborted_tools`（断在执行工具时） | 中止原因 `interrupted` | `aborted`，带取消原因 |

**一样：中断不能变成「拒绝」。** codex 的源码里同一句注释写了两遍：先让被中断的任务看到取消，再丢掉等你点头的审批，否则这个审批会先被当成「用户拒绝了」交给模型。Claude Code 2.1.296 修过同一类问题：会话关闭打断了一个工具调用，恢复后的子代理却被告知「用户拒绝了这次调用」。对模型来说，「被拒绝」意味着用户不同意，它会换方向；「被中断」只是用户叫停了，接下来听用户的。

**一样：拦截点上的中断要按「没通过」处理。** Claude Code 2.1.296 修过：UserPromptSubmit 钩子运行时按 Esc，会让没检查过的提示词直接发给模型。codex 的中断顺序、dsh 的 `agent/pre-step` 拒绝后不开始这一步，都是同一个思路：拦截点上出了意外，不能放行。

**不一样：要不要告诉模型「是你打断的」。** codex 写得最明确：用户是故意打断的，后台命令可能还在跑，被中止的命令可能执行了一半。dsh 不加说明，而是把用户已经看到的半截回复留在历史里，包说明的理由是让下一次请求包含用户看到的内容。Claude Code 留了一段标记，原文文档没给。

**不一样：进程崩溃之后。** 三家都给没有结果的工具调用补结果，措辞的用心程度不同：codex 补的内容就是 `aborted`；dsh 分「还没开始」和「开始了但结果未知」两种，后者明确告诉模型，可能有副作用的操作要先核实外部状态或问用户，不要盲目重试；Claude Code 补什么文档没写，但提供了一个开关 `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`，恢复会话时让模型从停下的地方接着做。

## 出错了怎么办

<!--@include: ./figures/turn-loop-stream-error.svg-->
<figcaption>回复写到一半出错时三家的处理。Claude Code 的做法从 2.1.199 起是这样，之前会丢掉已经写出的部分、整轮报错。</figcaption>
</figure>

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 默认重试 | 10 次 | 输出流中断 5 次，发请求失败 4 次 | 5 次 |
| 间隔 | 指数退避 | 服务端建议的时间优先，否则指数退避加抖动 | 0.5 秒起翻倍，最长 10 秒，抖动 10% |
| 断网 | 计入重试次数；无人值守模式下 429、529 无限重试 | 不计次数，间隔 5 秒起翻倍到 60 秒，一直重连 | 算「传输失败」，计入次数；可以改成无限重试 |
| 用完之后 | 这一轮结束，运行 StopFailure 钩子；SDK 结果的 `subtype` 仍是 `success`，`is_error` 为 true | 这一轮以失败结束，带错误类型；正在执行的目标挂起 | 这一轮以 `error` 结束，给没结果的工具调用补结果 |

**一样：重试不能让工具执行两遍。** 回复写到一半出错时，里面可能已经有完整的工具调用。三家用三种办法保证它不会因为重试再执行一遍：

- **Claude Code** 看进度：还没有任何完整内容就重发；已经有完整的文字或工具调用，就不重发这次请求，保留完成的部分、执行完整的工具调用，带着结果接着跑。
- **codex** 把完成的部分先记进历史：工具调用一完整就开跑，出错后等它们跑完、结果记进历史，再用这份历史重试。模型在重试的请求里能看到自己刚才调了什么、结果如何。
- **dsh** 从根上避开：工具要等整条回复成功才执行，失败的回复里一个工具都没跑过，整条作废、原样重发就行。

dsh 的办法最简单，代价是工具不能边收边跑；codex 最省时间，代价是重试的请求和原来那次不一样了。

**一样：上下文超长不直接重试。** 原样重发还会被拒。Claude Code 先调小这次请求的输出上限，不行再压缩；codex 在两次请求之间按阈值提前压缩；dsh 的压缩插件在这一步里剪枝或摘要后再重发。

**不一样：断网时等多久。** codex 默认一直重连，不消耗重试次数；Claude Code 和 dsh 都计入次数，次数用完就以出错结束，除非打开无人值守的无限重试（Claude Code 的 `CLAUDE_CODE_RETRY_WATCHDOG`、dsh 的 `always` 策略）。

## 什么时候停

|  | Claude Code | codex | dsh |
| --- | --- | --- | --- |
| 结束原因的取值 | SDK 结果 `subtype` 5 种，`terminal_reason` 19 种 | 一轮的状态 3 种（完成、中断、失败），中止原因 4 种 | 7 种（`completed`、`max-tokens`、`blocked`、`aborted`、`error`、`interrupted`、`forked`），插件可以扩展 |
| 钩子让它接着干 | Stop 钩子，连续最多 8 次 | Stop 钩子，不限次数 | 没有 Stop 钩子；插件可以在收尾检查时塞一条插话 |
| 目标：谁判断做完了 | 另一个模型，每轮结束后对照条件检查 | 干活的模型自己，用 `update_goal` 标记 | 干活的模型自己，用 `update_goal` 标记 |
| 目标的额度 | 不限轮数，可以在条件里写「20 轮后停」 | 可以设 token 预算 | 默认最多 256 轮 |
| 重复调用同一个工具 | 文档没写有检测 | 没有检测 | 连续 3、5、8 次时提醒模型，不拦截 |

**一样：「为什么停」是固定的取值。** 三家都把结束原因做成一组固定的值，而不是一句自由文本。dsh 分得最细：`interrupted` 只在崩溃恢复时补记，循环自己从不发出，所以「被取消」和「崩掉了」在日志里是两个值，各有唯一的来源。Claude Code 把中断再分成「断在输出时」和「断在执行工具时」两种。

**不一样：目标做没做完，谁说了算。** Claude Code 的 `/goal` 用另一个模型，每轮结束后对照条件检查对话内容，文档的说法是由一个新的模型、而不是干活的那个来判断。codex 和 dsh 让干活的模型自己调用 `update_goal` 标记完成，codex 在续跑提示里要求它先做一遍完成审计，dsh 要求连续 3 轮受阻才能报告受阻。

**不一样：额度用什么量。** Claude Code 在 `-p` 模式下能按美元设花费上限，也能按步数设上限；codex 只有目标的 token 预算；dsh 只有目标的轮数上限，包说明特意写明它不计 token、钱和时间。

**不一样：原地打转。** 只有 dsh 默认装了检测：同一个工具、同样的参数连续调用 3、5、8 次时，给模型追加一段提醒，只提醒不拦截。codex 源码里没有这类逻辑；Claude Code 文档没写，能起作用的是 Stop 钩子 8 次的上限、`-p` 模式的步数和花费上限这些闸。

**不一样：Stop 钩子续跑的上限。** Claude Code 连续 8 次后忽略拦截，模型每调一次工具计数清零；codex 不限次数，要钩子自己看 `stop_hook_active` 避免无限续跑。
